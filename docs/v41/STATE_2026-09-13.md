# Measured state, end of 2026-09-13 — input for "what is the path to target?"

## Targets
**1000 tok/s prefill @ 100K context; 30 tok/s decode; validated end to end.**

## Hardware
* box 1: 96 GB (usable expert pool ~52-62 GB; 76 GB OOMs on the long-prefill path),
  RX 9070 XT 16 GB dGPU over OCuLink (~7 GB/s), Strix Halo iGPU (~256 GB/s).
  NVMe on **dm-crypt**: 2.70 / 4.11 / 4.22 / 4.31 GB/s at 1 / 4 / 8 / 32 threads.
* box 2: 128 GB (~110 GB usable), iGPU only, USB4. RTT ~436 us at B=1, ~26-33 ms
  per layer at prefill chunk sizes (~12 ms of that is link).
* Model: 40 layers, 384 routed experts/layer, 6 activated, 18.8 MB/expert,
  **289 GB of experts total**. CED: prefill runs only the 20 encoder layers;
  decode runs all 40.

## Where we are (all measured today, output validated identical to single-box)
* **prefill 19.4 -> 109.7 tok/s** on a 4768-token prompt.
* **decode 0.8 -> 4.6 tok/s** warm (256-token generation; cold-start average is
  lower, and the pool persists across requests so a session runs warm).

Landed: union paging (page the routed union, not all 384/layer); window/pool
tuning; two-box expert split on BOTH prefill and decode with the RTT overlapped;
encoder-skewed box-2 assignment; batched miss service; parallel per-miss pread.

## Decode budget (~200 ms/token at 62 GB pool)
| | ms | note |
|---|---|---|
| expert paging | **163** | 15.7 misses x 10.4 ms |
| dGPU compute | 27 | attention, projections, shared expert |
| iGPU routed MoE | 10 | box 1's 3.9/6 share |

Per miss (11.5 ms): pread 8.67, repack 1.50, H2D 1.18, alloc 0.17.

**The MoE kernel is NOT the problem**: isolated bench
(`tests/bench_mxfp4_moe_b1.rs`) gives 394 us/launch = **190.9 GB/s = 1.3x off the
256 GB/s roofline**, i.e. 75% of peak. The `igpu.routed_moe` *stage* reads
160-390 ms/token but that is ~90% stream idle while the host pages experts.
dGPU legs are 1.4-1.7x off roofline. There is no kernel win in decode.

Implication: at ZERO misses decode compute is ~37 ms = **~27 tok/s**; with DSpark
(~2.4x, E[tok] 4.13, not implemented) ~65. But zero misses needs ~289 GB resident
and two boxes hold **~180 GB**.

## Prefill
* iGPU-MoE-bound: the dGPU's top stages are `.wait` (peer-push 30 ms,
  ffn_combine 14 ms per chunk) and it idles; `igpu.routed_moe` dominates.
* **chunk-major**: every layer re-pages for every chunk. 4768 tokens = 866 GB of
  reads; at 100K it is ~14 TB. Layer-major (all chunks through layer L before
  L+1) pages each layer ONCE: ~76-144 GB *independent of prompt length*.
  Carried state at 100K is 8.2 GB (HC_DIM = 5120x4 f32 = 80 KB/token), plus
  ~312 GB of PCIe transit if done naively at G=1.
* **B_MAX cannot rise at 100K**: attn_scores is 6.2 MiB per lane row at 100K
  (3157 MiB at rows=512); B_MAX=2048 needs ~16.6 GB against a 16 GB dGPU.
* The range driver `forward_prompt_batch_v2_pipelined_range(.., layers, ced)`
  already runs a layer RANGE with two lanes, so group-major is buildable with
  little new code, at the cost of a warmup/cooldown bubble per (chunk, group).

## Known open items
* **KV snapshots are DISABLED under v41** (`engine_worker.rs:1783`, Engram
  sequence desync), so every agentic turn re-prefills the whole conversation.
  User has explicitly deferred this — it is a real-usage fix, not a target fix.
* DSpark not implemented at all (`hf_v41.rs:23`). Corrected reference acceptance
  is d1 0.843 greedy / 0.851 rejection, **E[tok] 4.13**.
* `ExpertPager::remap_dev` is one buffer shared by two prefill lanes at different
  layers — safe only while ownership is layer-uniform within the encoder.
* Assignment is a real trade: box 2 `L0-L19:116-383` gives prefill 109.7 /
  decode 3.8; `all:250-383` gives prefill 70.8 / decode 4.5. Box 1's decode
  request count is invariant (156/token) but its LRU hit rate is not.
* pread runs at 1.46-2.17 GB/s against 4.31 GB/s at depth; dm-crypt (not the
  drive) appears to be the serialiser. Parallel per-miss pread is in and looks
  like -20% on ms/miss, clean A/B still running.
* Repack (1.50 ms/miss) is a bit-level nibble permutation (HF stores lo/hi
  halves, ggml wants pairwise-interleaved 17-B blocks). Proposal: do it on the
  GPU instead of changing every MXFP4 kernel's indexing.

## Workload (from the user)
Agentic: one medium prefill, then decode / short prefill / decode / ... needing
fast turnaround. Occasionally very long prefills (100s of Ktok) after memory
edits, context compression, or a cache miss.
