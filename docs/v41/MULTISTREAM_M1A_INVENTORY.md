Produced by a code-search pass over `forward_layer.rs`, `engine.rs`, `state.rs`,
`scratch.rs`, `batch_scratch.rs` and the kernel wrappers, as the input for the
batched multi-stream step (docs/v41/MULTISTREAM_DECODE_PLAN.md section 3). Every
row cites file:line; nothing here is a recommendation.

What it changes in the plan (recorded in MULTISTREAM_DECODE_PLAN.md 3.3, rev 1.2):
batched twins (B rows of ONE sequence) already exist for every stage except the
sampler, and their only single-sequence assumption is ONE KV base pointer plus a
uniform per-row stride (`comp_kv_batch_stride`, one `raw_kv` base with
`n_raw_offset_per`). Per-row base offsets into one arena allocation per KV-source
layer remove that assumption without touching the kernels' arithmetic.

## Finding 1 — Exact per-row attention state in `HetLayerState` / `HetCompressorState`

**Raw SWA window** (`state.rs:439-457`):
- `HetLayerState::kv_cache: DeviceBuffer<u16>` (f16), capacity `KV_CACHE_ROWS = SWA_WINDOW + B_MAX` rows × `N_HEAD_DIM=512` (`state.rs:21`). One buffer per (layer, sequence).
- `n_raw: u32`, `raw_off: u32` (`state.rs:441,448`). Live window = rows `[raw_off, raw_off+n_raw)`; **decode never slides rows**, it appends at `slot = raw_off + n_raw` (`forward_layer.rs:911`) and then advances `n_raw` (until `SWA_WINDOW`) or `raw_off` (`forward_layer.rs:928-932`). Wrap = two-hop D2D compaction to slot 0 (`forward_layer.rs:934-951`).
- **Written by**: `kv_cache_append` (`forward_layer.rs:918-925`) — one 512-thread WG, row `slot`. **Read by**: `kv_win = ls.kv_cache.slice_view(raw_off*512, n_raw*512)` (`forward_layer.rs:1337-1340`), consumed by `attention_swa` (row 37), `attention_mixed_score_b1_htiled_wmma` (row 50), `attention_mixed_wsum_b1_htiled_ksplit_ldsv` (row 52). The kernels see rows `[0, n_raw)` of the sliced base pointer — the offset is applied **host-side by the slice**, not by a kernel argument.

**Compressed store** (`state.rs:271-291`, `state.rs:459-465`):
- `HetCompressorState::comp_kv: CompKvStore` (`state.rs:44-50`) — under v41 always `F16(DeviceBuffer<u16>)` for the main compressor (`state.rs:206-216`, since `ratio ∈ {1,2}` never hits the `ratio==4` fp8/e2m1 arms). Row `i` = elements `[i*512, (i+1)*512)`. Capacity `max_n_comp = ceil(n_kv_max/ratio)` rows (`state.rs:205`).
- `n_comp: u32` (`state.rs:161`) — the append index and the dense read length.
- `state_kv`, `state_score`: `DeviceBuffer<f32>`, `ratio*coff × width` = `ratio × 512` floats, **allocated on the iGPU** (`state.rs:194-199`) — the running segment accumulators. Indexed by `row = pos % ratio` (`forward_layer.rs:982`), with the positional-encoding slice keyed by `pos_mod = pos % ratio` (`forward_layer.rs:981`).
- `index_k: Option<DeviceBuffer<u8>>` (`state.rs:175`) — packed E2M1 keys, `E2M1_KEY_ROW_BYTES = 80` per row, row `i` = bytes `[i*80, (i+1)*80)`. `n_index_comp: u32` (`state.rs:178`) advances in lockstep with `n_comp` (`forward_layer.rs:1149`).
- **Written by**: `compressor_state_write` (row 26), `compressor_pool` (row 27), `comp_kv_append` (row 35), `index_kv_append_e2m1` (row 34). **Read by**: `indexer_score_wmma_mw_e2m1` (row 43, reads `index_k`), `indexer_gather` (row 48, reads `comp_kv`), and directly by `attention_mixed_*` via `c.comp_kv.dense_f16(n_comp_full, …)` on the dense path (`forward_layer.rs:1855`).
- **Sharing/lending**: under v41 only the 4 KV-source layers own a `compressor` (`config.rs:146`, `state.rs:459`); reuse layers get it moved in/out around the forward by `engine.rs:1044-1048` / `engine.rs:1204-1207` and `HetModelState::with_kv_source` (`state.rs:391-408`), with a repair pass `restore_compressor_lending` (`state.rs:373-388`) at every forward entry.

## Finding 2 — `publish_pos_slot`, and who consumes `pos_dev` / `kv_slot_dev`

`publish_pos_slot` (`engine.rs:614-630`) issues **two `hipStreamWriteValue32` on `self.dgpu.compute`**: `dgpu_scratch.pos_dev = pos` and `dgpu_scratch.kv_slot_dev = slot`. Both are 1-element `DeviceBuffer<u32>` (`scratch.rs:200-201`, allocated `scratch.rs:401-402`). The same pair is written inline once per token in `forward_token_impl` (`engine.rs:958-966`), taking `slot` from **layer 0's** counters on the argument that all layers advance in lockstep (`engine.rs:953-957`). `publish_pos_slot` exists specifically because a layer-major driver breaks that invariant (`engine.rs:607-613`).

Consumers of those two buffers in the layer path are exactly two call sites, both inside the `qkv_chain` merged graph:
- `de.rope.launch_forward_pdev(..., &dgpu_scratch.pos_dev, ...)` → `rope_tail_pdev` (`forward_layer.rs:782`; wrapper `rope.rs:94-107`, kernel launch `rope.rs:163-174`).
- `de.fp8.launch_kv_post_fused(..., &dgpu_scratch.pos_dev, &dgpu_scratch.kv_slot_dev, ...)` → `kv_post_fused` (`forward_layer.rs:785-797`; wrapper `compressor.rs:175-224`, kernel `fp8_e4m3fn.hip`).

**Under `v41` that whole branch is disabled** — the gate is `if *QKV_GRAPH && !standalone_graphs && !cfg!(feature = "v41")` (`forward_layer.rs:769`), with the reason given at `forward_layer.rs:801-805` ("needs a device-slot kv_append for graph capture"). So in the V4.1 decode path today `pos_dev`/`kv_slot_dev` are written every token and **read by nothing**; the live path uses host `pos` in `rope.launch_forward` (`forward_layer.rs:825`, `878`, `1074`, `1088`, `1475`, `1955`) and host `slot` in `kv_append.launch` (`forward_layer.rs:918-925`). The only other `pos_dev`/`slot_dev` in the tree belong to `MtpState` (`mtp.rs:512,606,1083-1124`) and are separate buffers. `publish_pos_slot`'s only caller is the speculative-verify driver at `engine_worker.rs:3725`.

A device-slot append kernel already exists and is unused by decode: `KvCacheAppend::launch_slotdev` → `kv_cache_append_slotdev`, `grid=(1,1,1) block=(head_dim,1,1)` (`kv_cache_append.rs:92-108`).
