# Code review of the uncommitted V4.1 port (2026-09-13) — findings + disposition

Adversarial read-only review of ~1900 added lines / 38 tracked + ~20 new files (the four
expert-pager files were excluded as a concurrently-edited moving target).

## FIXED in this pass
1. **HIGH — `EngramHash::compress` panicked on image tokens (multimodal blocker).**
   `engram_hash.rs` indexed `token_map[id as usize]` unchecked. Image spans carry the IMAGE token
   (129264) and `v4flash_vision::synthetic_token_id` values past `token_map.len()`; a negative id
   wrapped through `as usize`. Serving any image would panic the worker mid-request.
   **Fix:** bounds-checked, out-of-range/negative -> `pad_id`. NOTE: this stops the crash but is NOT
   full parity — the reference masks image tokens out of Engram entirely (`engram_mask = ~image_mask`).
   Threading that mask through the gate is still REQUIRED for correct multimodal (see VISION_PORT.md).
2. **MEDIUM — `EngramTable::gather` panicked on an empty id list** (`ids.chunks(0)`). Now returns `Ok(())`.
3. **MEDIUM — fp8 block-scale geometry was inferred by division.** Under ceil-tiling a non-dividing
   dim can satisfy `out % sr == 0` by coincidence while the derived block is wrong, mis-scaling every
   element (single-prompt parity would not necessarily catch it). Verified every V4.1 fp8 tensor is
   exactly 32x32 tiled today (layers 0/2/20/39); now **asserts exact tiling and refuses to guess**.
4. **MEDIUM (perf, hits the expert tier directly) — every expert read issued `POSIX_FADV_DONTNEED`,
   dropping its own page cache.** The M7 pager exists to re-read experts as its LRU refills, so each
   refill was forced back to SSD instead of RAM. `read_expert_raw` now uses `read_range_into_cached`
   (the path Engram already uses). **This directly affects the 30 tok/s decode target.**
5. **Test pinned the wrong thing:** `tokenizer_json_vs_gguf` fed `a.pre` into the JSON loader, proving
   "same pre => same tables" but never that `"joyai-llm"` (hardcoded in engine_worker.rs) is correct.
   Now asserts the literal.

## OUTSTANDING (tracked, not yet fixed)
- **Test suite overstates coverage.** `hf_v41_fixture`, `tokenizer_json_vs_gguf`, `weight_src_arms`,
  `engram_table::gather_matches_reference_rows`, `engram_hash::matches_reference_self_check` and
  `weight_contract_models` all `return` early with an `eprintln!("skip")` when their env/fixture is
  missing, so a plain `cargo test` reports them GREEN. **"byte-exact vs the converter" and
  "tokenizer id-for-id" only hold when those env vars are set.** Make them `#[ignore]` so a green run
  stops implying coverage it does not have. (This corrects an earlier overstatement of mine.)
- `gather_position` spawns 24 OS threads per call (~48 spawn/joins per token vs a 33 ms budget).
- `with_kv_source` restores on `Err` but not on a **panic** in the closure, and is not re-entrant.
- u32 overflow in the `fp4_kv` / `engram_gate` launcher size guards (the only bounds protection).
- `model_shape()` ignores `expert_limit`, so the compiled-vs-loaded guard passes and the mismatch
  surfaces later as `expert {e} >= {n_expert}` — fail-loud, but in the wrong place.

and 2^(e-128) cancel); `fp8_ue8m0_scale` exact incl. the power-of-two case; shuffle reductions safe
