### A1. `lh.remap_h2d` = 55.5 ms/step is a device-wide barrier, not a 1536-byte copy â 17.5% of the step
`crates/v4flash-hip/src/stream.rs:24,33` + `crates/v4flash-kernels/src/het/expert_pager.rs:1324-1328,2730-2740`

Every stream in the process is created blocking:
```rust

sys::hipStreamCreateWithPriority(&mut raw, sys::HIP_STREAM_DEFAULT, priority)      // stream.rs:33

```
ROCm defines `hipStreamNonBlocking 0x01` as "Stream does not implicitly synchronize with null stream" â flags 0 means it *does*. And `upload_remap` issues a **null-stream** `hipMemcpy`:
```rust

    let l = self.cur_layer.clamp(0, N_LAYER - 1) as usize;
    self.device.set_current()?;

```
The code already asks the question at `expert_pager.rs:2730-2733`:
> *"With zero misses this 1536-byte copy is the ONLY device op in the call, and the call measures ~10.6 ms/layer-lane â so this timer says whether a tiny synchronous `hipMemcpy` is stalling on the iGPU's queued MoE work."*

## Patterns

Four systemic habits, in order of how much they cost:

**1. A timer's name describes the phase it lives in, not the work it brackets.** `lh.pager_block` is a routing-and-RPC block (A4). `box2.compute_ms` is `service â page` where `service` includes an idle merge wait and `page` triple-counts its own sub-phases (B1-B3). `dgpu_busy_us` in `het.token.summary` sums the `.wait` stall scopes (B10). `decode_pread_gbps` divides by a sum over threads. Every one of these was created by wrapping an existing scope in a guard named after the scope's *intent* rather than its *contents*, and every one was already contradicted by a comment elsewhere in the same file. **The tell:** when a timer encloses another timer, the outer name is almost always wrong. Three of them (`pager_ms â sel_sync`, `read_ns â h2d_ns`, `busy â wait`) are literally documented as "not additive" in a note that stops short of saying the enclosing name is therefore a lie.

**2. **3.
